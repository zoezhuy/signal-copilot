# 求职材料文案与面试讲述稿

## 简历项目描述

**招聘沟通信号分析助手｜AI Recruiting Signal Copilot｜个人项目｜2026.05—至今**

- 独立设计并开发中英文双语招聘沟通 Web MVP，覆盖求职者面试推进判断与招聘方候选人 Offer 接受风险识别两类场景。
- 建立可解释的沟通信号框架，将对话结构化呈现为积极信号、风险信号、原文证据、证据覆盖度及跟进建议，并制作 12 组双语演示结果。
- 围绕竞品 Offer、薪资顾虑、决策时间、入职日期和招聘流程推进等关键场景，设计双角色分析逻辑与低证据拒答机制。
- 将负责任 AI 原则转化为产品交互：区分输出来源、提示个人信息、展示判断证据、避免候选人评分，并强调人工复核和持续沟通。
- 使用 Figma Make 完成交互原型，并基于 React、TypeScript、Tailwind CSS 实现可运行前端；当前自由输入采用本地可解释规则，已规划服务端模型、自动脱敏及 ATS 集成路线。

## 作品集首页摘要

招聘决策中的重要信号常常散落在非结构化聊天里。这个项目探索如何在不评价人的前提下，把对话中的推进、顾虑和不确定性转化为可核对的证据与更好的跟进动作。我负责从问题定义、信号框架和负责任 AI 边界，到双语交互设计及前端 MVP 的完整过程。

## 60 秒面试讲述

我观察到候选人和招聘方都会过度解读聊天信息：候选人不知道“还在面试”意味着什么，招聘方也可能在 Offer 被拒时才发现候选人的真实顾虑。所以我没有把产品定义为预测录用或入职概率，而是做成一个沟通信号助手。它有求职者和招聘方两种模式，每个结论都必须展示原文证据，并给出继续沟通的建议。实现过程中，我发现固定 mock 结果会让自由输入产生虚假的可信感，因此增加了本地可解释规则、证据不足状态和输出来源标识。这个项目最能体现我对招聘流程、候选人体验以及负责任 AI 产品边界的综合理解。

## 常见追问

**为什么这是 HR 项目，而不只是前端项目？**

核心工作不是搭建页面，而是定义哪些招聘沟通信号可以被观察、哪些推断不应该做，以及如何让建议改善候选人体验。

**如何证明它有效？**

当前项目验证的是概念和交互完整性，不声称已经验证业务效果。下一步计划让招聘从业者完成真实任务，并评估证据引用准确率、低证据拒答率、建议可执行性和过度信任风险。

## 不建议使用的表述

- “准确预测候选人是否会入职”
- “自动识别候选人忠诚度或稳定性”
- “已经完成微信小程序开发”
- “已经通过真实招聘数据验证”
- “AI 置信度等于录用或入职概率”
