# Signal Copilot Evaluation Plan

本文件说明 Signal Copilot 从作品集原型走向可验证产品时需要回答的问题。这里定义的是评估方案，不声称当前版本已经达到这些指标。

## 1. 评估目标

产品不评估候选人的能力、性格或“是否值得录用”。评估重点是：系统能否忠实地从文本中识别可观察的沟通信号，并给出安全、清晰、可执行的下一步建议。

## 2. 建议数据集

- 经参与者明确同意并完成匿名化的中英文招聘对话；
- 求职者与招聘方两种角色分别覆盖积极、等待、风险和证据不足情境；
- 样本应包含口语、省略、否定、模糊时间、多个 Offer 与薪资沟通等复杂情况；
- 标注人员至少包含一名有招聘经验的评审者；分歧需要记录和复核。

未经授权的真实候选人聊天记录不得进入测试集或仓库。

## 3. 核心指标

| 指标 | 定义 | 为什么重要 |
|---|---|---|
| 信号精确率 | 系统标记的信号中，经人工确认有文本依据的比例 | 减少凭空推断 |
| 信号召回率 | 人工标注信号中被系统识别的比例 | 减少遗漏关键顾虑 |
| 证据引用准确率 | 引用片段是否直接支持对应标签 | 保证结果可核对 |
| 低证据拒答率 | 信息不足样本中正确返回“证据不足”的比例 | 避免虚假确定性 |
| 建议可执行性 | 招聘从业者对建议是否明确、尊重且可采取行动的评分 | 验证实际使用价值 |
| 潜在伤害率 | 是否出现歧视、施压、过度推断或自动决策倾向 | 识别安全风险 |

## 4. 任务式可用性测试

邀请 5–8 名招聘从业者和求职者分别完成典型任务：识别下一步、核对证据、判断是否需要补充信息、准备跟进话术。记录任务完成率、完成时间、误解点、人工推翻结果的原因和建议采用情况。

## 5. 上线前门槛

- 每个结论都能返回到明确的原文证据；
- 证据不足时不得给出录用或入职概率；
- 不得基于敏感属性进行筛选、排序或推断；
- 用户能够编辑、忽略或推翻系统结论；
- 完成数据保留、删除、访问控制和审计设计；
- 在产品界面中持续标明结果来源、限制和人工复核要求。

## 6. 当前状态

当前仓库提供本地规则原型、人工审阅案例和自动化逻辑测试，尚未使用真实招聘数据完成准确性、公平性或业务效果验证。
