# Signal Copilot｜招聘沟通信号分析助手

> 一个面向求职者与招聘团队的中英文双语 Web 原型：从招聘对话中提取可核对的推进信号、风险信号和原文证据，帮助双方决定下一步如何沟通。

[在线体验](https://zoezhuy.github.io/signal-copilot/) · [完整案例研究](docs/CASE_STUDY.zh-CN.md) · [信号框架](docs/SIGNAL_FRAMEWORK.md) · [负责任 AI 说明](docs/RESPONSIBLE_AI.md)

- **项目类型：** 个人作品集 / 产品概念验证
- **个人职责：** 问题定义、用户流程、信号框架、交互设计、前端开发、测试与部署
- **技术栈：** React 18、TypeScript、Vite、Tailwind CSS、Vitest、GitHub Actions

## 30 秒了解这个项目

招聘流程中的关键信息经常散落在邮件和聊天记录里：求职者不知道“仍在面试其他人”意味着正常等待还是推进降温；招聘方也可能直到候选人拒绝 Offer，才意识到薪资、竞品 Offer 或入职日期仍有顾虑。

Signal Copilot 将这些非结构化对话整理为：

- **积极信号**：例如明确下一轮、具体时间、签约或入职意愿；
- **风险信号**：例如流程时间模糊、竞争 Offer、薪资顾虑或决策延期；
- **原文证据**：每个信号都附带触发判断的对话片段；
- **证据覆盖度**：表达当前文本包含多少可观察信息，不代表录用或 Offer 接受概率；
- **下一步建议**：把结果转化为尊重、明确且可执行的跟进动作。

这个项目不试图“预测一个人”，而是帮助用户更清楚地理解现有证据，并开展下一次更好的沟通。

## 产品如何工作

### 求职者模式

帮助求职者判断面试流程是否存在明确的推进信号、等待状态或结束信号，并获得不过度催促的跟进建议。

**典型场景：**

- 招聘方是否给出了下一轮面试或具体时间？
- “还在面试其他候选人”是否意味着已经被拒绝？
- 多久以及如何跟进，既表达兴趣又不过度施压？

### 招聘方模式

帮助招聘团队在 Offer 阶段识别仍需澄清的沟通风险，并将候选人的实际顾虑转化为下一步动作。

**典型场景：**

- 候选人是否明确表达了加入或签约意愿？
- 是否存在竞争 Offer、薪资差距或入职时间问题？
- 应该协调薪资、时间，还是安排用人经理进一步沟通？

### 体验流程

1. 选择 **求职者** 或 **招聘方** 模式；
2. 切换中文或英文；
3. 选择精选案例，或粘贴一段已匿名化的对话；
4. 查看总体判断、积极信号、风险信号及对应原文；
5. 根据建议准备下一次沟通，并由用户完成最终判断。

```mermaid
flowchart LR
  A[匿名化招聘对话] --> B{输入类型}
  B -->|精选案例| C[人工审阅的演示结果]
  B -->|自由输入| D[浏览器本地规则分析]
  C --> E[积极与风险信号]
  D --> E
  E --> F[原文证据与覆盖度]
  F --> G[下一步沟通建议]
  G --> H[人工复核与决定]
```

## 核心设计决策

### 1. 不展示“录用概率”或“入职概率”

一段聊天无法可靠预测人的最终行为。为了避免制造虚假的精确感，产品展示的是**证据覆盖度**，并把结论限制在对话中可观察的沟通信号。

### 2. 每个结论都必须能够回到原文

结果不仅显示标签，还展示触发该标签的文本片段。用户可以核对系统为什么做出判断，也可以推翻结果。

### 3. 信息不足时明确拒答

当文本没有提供时间、下一步或具体顾虑等有效信号时，系统返回“证据不足”，提示用户补充上下文，而不是自动补全事实。

### 4. 将建议设计为“继续沟通”

风险结果不会建议减少对候选人的投入或直接作出招聘决定，而是引导用户澄清薪资、时间、流程和真实顾虑。

### 5. 保留无需 API Key 的本地分析体验

精选案例用于展示理想的产品输出；自由输入则由透明的浏览器本地规则处理。这样访问者无需配置 API Key，也能直接体验核心交互，同时清楚知道结果来源和能力边界。

## 技术实现

```text
用户输入
   │
   ├── 精选案例 ──> 人工审阅结果
   │
   └── 自由输入 ──> 本地规则引擎 ──> 关键词匹配与证据句提取
                                      │
                                      └── 信号、覆盖度与跟进建议
```

- **React 18 + TypeScript**：组件化 UI、角色/语言/平台状态管理和类型约束；
- **Vite + Tailwind CSS**：快速开发、响应式布局与生产构建；
- **本地规则引擎**：按角色匹配中英文信号词，并返回命中的完整句子；
- **隐私优先**：当前自由输入只在浏览器内处理，不上传、不持久化；
- **Vitest**：覆盖积极信号、风险信号、证据不足和个人信息提醒；
- **GitHub Actions**：每次推送执行测试、类型检查和构建，并部署至 GitHub Pages。

## 负责任 AI 与隐私边界

Signal Copilot 是作品集原型，不是自动化招聘决策系统。

- 不评价候选人的能力、性格、忠诚度或“是否值得录用”；
- 不用于自动筛选、排序、拒绝候选人或撤回 Offer；
- 证据覆盖度不等于任何行为发生的概率；
- 请勿输入未经授权的真实候选人敏感信息；
- 所有结果都需要结合完整上下文进行人工复核。

更多信息见 [Responsible AI & Privacy Notes](docs/RESPONSIBLE_AI.md)。

## 已知限制

- 当前规则不能理解反讽、复杂上下文、跨消息关系或公司特定流程；
- 回复延迟无法仅凭正文可靠判断，需要结构化时间戳；
- 关键词匹配可能出现误报或漏报；
- 精选案例用于演示产品形态，不代表真实模型效果评估；
- 联系方式检测只是匿名化提醒，不是完整的数据脱敏方案；
- 项目尚未使用真实招聘数据完成准确性、公平性或业务效果验证。

## 下一阶段计划

4. 设计带结构化 JSON 和证据引用的服务端模型接口；
5. 增加自动脱敏、数据删除、访问控制与审计机制；
6. 在完成安全和效果验证后，再探索 ATS 集成。

## 项目反思

这个项目最重要的学习，不是如何给每段对话生成一个分数，而是如何约束产品不去回答证据无法支持的问题。对招聘 AI 产品而言，不确定性、隐私、解释能力和人工复核不应该只是免责声明，而应该成为产品流程的一部分。
